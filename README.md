# study-planner Cloudflare Worker

Worker مستقل برای آرشیو خودکار امتحان‌ها و تکالیف با Cloudflare D1 و Cron Trigger. این پروژه فقط Worker و دیتابیس را تغییر می‌دهد و به سایت/فرانت‌اند دست نمی‌زند.

## رفتار

- Cron هر دقیقه اجرا می‌شود؛ پس از پایان زنگ، آرشیو معمولاً حداکثر تا حدود یک دقیقه بعد انجام می‌شود.
- Migration دوم آرشیو خودکار را فعال می‌کند و برنامهٔ اولیهٔ سه زنگ را بر اساس زمان‌های اعلام‌شده وارد می‌کند.
- برنامهٔ محاسبه‌شده: زنگ ۱ از 08:55 تا 10:42، زنگ ۲ از 10:42 تا 12:30، زنگ ۳ از 12:30 تا 13:45. فاصلهٔ 08:55 تا 12:30 برابر ۲۱۵ دقیقه است؛ تقسیم آن بین دو فاصله، حدود ۱۰۷٫۵ دقیقه می‌شود. برای زمان‌های کامل دقیقه‌ای، مرز میانی 10:42 انتخاب شده است.
- این برنامه یک تخمین ریاضی بر اساس اطلاعات موجود است، نه ساعت‌بندی تأییدشدهٔ مدرسه. اگر زمان واقعی متفاوت باشد، باید از مسیر مدیریت `PUT /api/archive/schedule` آن را اصلاح کرد.
- منطقه زمانی پیش‌فرض `Asia/Tehran` است.
- تاریخ‌های ذخیره‌شده باید میلادی و به شکل `YYYY-MM-DD` باشند. تاریخ شمسی باید پیش از ذخیره به میلادی تبدیل شده باشد.
- امتحان‌های `upcoming` و `done` پس از پایان زنگ برنامه‌ریزی‌شده آرشیو می‌شوند؛ امتحان‌های `cancelled` آرشیو خودکار نمی‌شوند.
- تکالیف پس از موعد و پایان زنگ مربوطه آرشیو می‌شوند، اما وضعیت `todo`، `done` یا `skipped` حفظ می‌شود. آرشیو به معنی انجام‌شدن تکلیف نیست.
- ردیف‌های قدیمی که `period_number` ندارند دست‌نخورده می‌مانند؛ Worker زمان زنگ آن‌ها را حدس نمی‌زند.
- Worker با `archived_at` رکوردها را نشانه‌گذاری می‌کند. برای اینکه این رکوردها در سایت از فهرست فعال ناپدید شوند، فرانت‌اند باید `archived_at` را فیلتر کند؛ بنا به درخواست، این پروژه فرانت‌اند را تغییر نمی‌دهد.

## نصب یا به‌روزرسانی

از داخل پوشهٔ پروژه اجرا کن:

```bash
npm install
npx wrangler d1 migrations apply study-planner --remote
npx wrangler secret put ADMIN_TOKEN
npx wrangler deploy
```

اگر قبلاً Migration اول را اجرا کرده‌ای، دستور migration فقط Migration دوم را هم اعمال می‌کند. Migration دوم برنامهٔ سه زنگ بالا را جایگزین می‌کند و آرشیو خودکار را فعال می‌کند.

## بررسی وضعیت

```http
GET /api/health
GET /api/archive/status
```

برای مسیرهای تغییردهنده، هدر `Authorization: Bearer <ADMIN_TOKEN>` لازم است.

برای اجرای دستی:

```http
POST /api/archive/run
```

برای تغییر برنامهٔ زنگ‌ها:

```http
PUT /api/archive/schedule
Content-Type: application/json
Authorization: Bearer <ADMIN_TOKEN>
```

نمونهٔ بدنه:

```json
{
  "timezone": "Asia/Tehran",
  "periods": [
    { "period_number": 1, "start_time": "08:55", "end_time": "10:42" },
    { "period_number": 2, "start_time": "10:42", "end_time": "12:30" },
    { "period_number": 3, "start_time": "12:30", "end_time": "13:45" }
  ]
}
```
